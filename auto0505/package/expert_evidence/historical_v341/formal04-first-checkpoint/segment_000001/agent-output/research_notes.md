本段研究均在当前原生会话中进行，公开 GPU 只通过冻结 evaluate.sh 接口调用。

公开参考：https://github.com/wangjiangshan0725/RF-Solver-Edit/blob/main/FLUX_Image_Edit/src/flux/sampling.py 。最初尝试的 RF-Solver 仓库路径返回 HTTP 404；通过公开 GitHub 仓库搜索改正了 URL，没有访问服务端文件。

参考实现的更新为 x_mid=x+h*v/2，D=(v_mid-v)/(h/2)，x_next=x+h*v+h²*D/2，代数上等于显式中点法。对于线性测试方程，单步往返因子 R(z)R(-z)=1+z⁴/4，所以同一组节点并不能消除往返误差。这给出研究节点分布而非单向生成默认分布的理由。

初始设想是低噪声端加密可能有利。自写一维双峰条件速度场代理也支持负 logit 偏移，但真实公开结果推翻了这一方向的初步预测：均匀节点 PSNR 17.9593067883，低于 Starter 19.3615771375，11/12 图退化。已准备的负 μ=-0.63 候选因此未发出 GPU 请求，改为 μ=1.20。CPU 代理的结果没有记作公开分数。

BF16 对齐的动机来自真实 Starter 回执所列 dtype=bf16。对于 [0,1]，1/128 网格上的节点和 1/256 网格上的中点均能精确表示，步长也可以精确表示。普通均匀和 logit 网格的时间舍入误差可达约 0.0019；自写位级 BF16 舍入检查已保存在 research_bf16_alignment.json。改变节点同时改变了积分误差，不能仅据舍入误差断言重建更好。

第三轮候选草案采用 t=1-s²，即时间密度正比于 (1-t)^(-1/2)，着重细分噪声端而无需把低噪声端区间拉得很长。将连续目标投影到 1/128 网格，并强制至少一格和为剩余节点预留格数，避免因舍入产生重复节点。正式参数的高端间隔为 0.0078125，低端间隔为 0.078125；节点、中点、h 和 h²/2 的 BF16 舍入误差均为零。它是否进入正式第三轮，仍根据第二轮的真实反馈决定。

第二轮 μ=1.20 实测 PSNR=19.5468178616（保留）；第三轮确实采用该平方与 BF16 对齐草案，实测 PSNR=19.6116223289（保留）。两轮差为 +0.0648044673 dB，尚不能把收益归因于单独的对齐操作，因为密度形状同时改变。第三轮期间额外获取公开 layers.py 时发生网络读取超时，没有使用未取得的源码作决策。
